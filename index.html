⚠ Why naive is so slow

Both approaches make the same 3 recursive calls. But naive recursion recomputes d[i][j] every time it is needed — exponentially many times. DP computes each cell exactly once and stores it. This is the definition of overlapping subproblems — the core reason DP exists.

Why always Θ(mn) — no exceptions

The DP table has (m+1)×(n+1) cells. Each takes O(1) to compute (one comparison + one min of 3 values). Total = Θ(mn) exactly. No early exit, no pruning, no best case. This is why the bound is Θ (tight) not just O (upper bound).

① Optimal Substructure

d[i][j] is built from three already-solved subproblems: d[i][j-1] (insert ←), d[i-1][j] (delete ↑), d[i-1][j-1] (match/sub ↖). The globally optimal solution contains optimal sub-solutions — this is the DP guarantee.

② Overlapping Subproblems

In naive recursion, the same cell is computed many times from different paths. DP stores each result exactly once: O(mn) total vs O(3mn) naive. Without memoization, every recursive path recomputes every shared ancestor cell.

Click Animate to see which cells are shared dependencies when computing d[2][2] for "ab"→"ba". The purple cells are computed multiple times in naive recursion — DP stores them once.

Why this matters

For strings of length m and n, naive recursion has an exponential call tree. DP collapses this to exactly (m+1)×(n+1) computations — one per cell — because each cell is solved once and looked up in O(1) for every future reference. This is why memoization (top-down DP) and tabulation (bottom-up DP, used here) both achieve O(mn).

Greedy makes the locally best choice at each step without looking ahead. For edit distance, local optimality does not guarantee global optimality.

❌ Greedy: "abc" → "cab"
abc → cab
Step 1: 'a'≠'c' → sub → cbc (+1)
Step 2: 'b'≠'a' → sub → cac (+1)
Step 3: 'c'≠'b' → sub → cab (+1)
Cost: 3
✅ DP Optimal: "abc" → "cab"
abc → cab
Step 1: insert 'c' → cabc (+1)
Step 2: delete 'c' → cab (+1)

Cost: 2

Greedy cost: 3. DP cost: 2. Greedy substituted each character independently, missing the globally cheaper insert+delete strategy that DP finds by considering all predecessors simultaneously.

What if we used other paradigms?

Greedy: No natural greedy choice — substituting character by character does not minimise total cost. Divide & Conquer: Subproblems overlap (d[i][j] is shared by multiple parent cells) so D&C would recompute them. DP: Both conditions satisfied — it is the natural fit.

The DP table fills row by row, left to right. When we compute d[i][j], all three predecessors are already available because they are to the left or above.

d[i][j] depends on: d[i-1][j-1] ↖ diagonal (previous row, previous col — match/sub) d[i-1][j] ↑ above (previous row, same col — delete) d[i][j-1] ← left (same row, previous col — insert) Fill order: row by row, left to right (bottom-up). All three predecessors are always computed before d[i][j] needs them.
Base Cases — why they matter

d[i][0] = i  (column 0)

Cost to transform the first i characters of source into an empty string. Answer: delete all i characters. Without this, cells in column 0 have no valid predecessor.

d[0][j] = j  (row 0)

Cost to transform an empty string into the first j characters of target. Answer: insert all j characters. Without this, cells in row 0 have no valid predecessor.

The traceback searches backward through the DP table from d[m][n] → d[0][0], following the minimum-cost predecessor at each cell. This is the searching step in this algorithm.

Why traceback is the search step

The traceback is a path search through the DP table. At each cell it asks: "which of my three predecessors gave me this minimum value?" It searches left (insert), up (delete), or diagonal (match/sub) until it reaches d[0][0]. Without this search, the table gives you a distance but no edit sequence — the algorithm is half-complete.

Why min() is the matching/search step

The min(insert, delete, replace) call is where the algorithm searches for the best match between source and target characters. It evaluates all three alignment options simultaneously and selects the optimal one. Removing it — or forcing only one operation — breaks the search and produces wrong distances.

Base cases anchor the entire search

Row 0 and column 0 represent transformations to/from the empty string. They are the known starting points that the DP search builds on. Without them, every cell in the table references uninitialized values and the entire computation fails — just like a search with no starting node.

📖 Learn — Edit Distance (Levenshtein)

The Edit Distance between two strings is the minimum number of single-character operations needed to transform one string into the other. Introduced by Vladimir Levenshtein in 1965. Reference: Cormen et al., Introduction to Algorithms, Problem 15-5.

🔤 What is Edit Distance? ▼

Given two strings S and T, the edit distance d(S,T) is the minimum number of insert, delete, or replace operations needed to transform S into T.

←
Insert
d[i][j-1] + 1
Add a character into source to match target. Arrow ← in table.
↑
Delete
d[i-1][j] + 1
Remove a character from source. Arrow ↑ in table.
↖
Replace
d[i-1][j-1] + 1
Substitute one character for another. Uses diagonal ↖.
↖
Match
d[i-1][j-1] + 0
Characters are equal — inherit diagonal at zero cost. Always preferred when available.
📐 Recurrence Formula ▼
d[0][0] = 0 d[i][0] = i (delete all i source chars to reach empty) d[0][j] = j (insert all j target chars from empty) d[i][j] = d[i-1][j-1] if S[i] = T[j] ← FREE match d[i][j] = 1 + min( d[i][j-1], ← insert T[j] d[i-1][j], ↑ delete S[i] d[i-1][j-1] ) ↖ substitute

🧠 Key Concepts ▼

✅ Optimal Substructure

d[i][j] depends only on 3 already-solved subproblems. Global optimum built from local optima.

🔁 Overlapping Subproblems

Naive recursion recomputes cells exponentially. DP stores each result once: O(mn) vs O(3mn).

↔ Symmetry

dist(S,T) = dist(T,S). Swapping source and target always gives the same distance.

💾 Space Optimization

Only 2 rows needed if you don't need the path. Space drops from O(mn) to O(min(m,n)).

⚠ Common Mistakes ▼
❌ Off-by-one indexing
Using S[i] directly. Always use S[i-1] and T[j-1] inside the loop.
✅ Correct
Access S[i-1] and T[j-1]. Index 0 in the table = base case (empty string).
❌ Cost 1 on match
Setting cost=1 when S[i-1]=T[j-1]. A match is free — cost must be 0.
✅ Correct
cost = (S[i-1]===T[j-1]) ? 0 : 1. Only substitutions cost 1.
❌ Forgetting base cases
Starting the fill loop without setting row 0 and column 0 first. Cells that reference d[0][j] or d[i][0] will get wrong values.
✅ Always set base cases
Set d[i][0]=i for all i and d[0][j]=j for all j before the main loops begin.

The DP Matrix — what you'll see

The algorithm fills a grid called the Dynamic Programming (DP) matrix. Each cell d[i][j] stores the minimum edit distance between the first i characters of the source and first j characters of the target.

■ Source chars (left)  ·  ■ Target chars (top)  ·  ■ Match (free)  ·  ■ Substitute (+1)  ·  ╌ Traceback path (answer = 1)

The bottom-right cell always contains the final answer — the minimum edit distance between the two full strings.
